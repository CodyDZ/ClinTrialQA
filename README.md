# ClinTrialQA

**ClinTrialQA** is an automated benchmark for evaluating the *epistemic calibration* of language models over real clinical trial evidence. Given a clinical question and a curated set of PubMed abstracts, a model must synthesize the evidence, identify which abstracts are irrelevant, and express a confidence level that accurately reflects the strength and consistency of that evidence.

## Task Description

### Motivation

A common failure mode in clinical AI is *overconfidence*: a model presents a confident recommendation even when the underlying evidence is thin, mixed, or contradictory. ClinTrialQA operationalizes this problem as a structured task. Each item presents a model with:

- A yes/no clinical question (e.g., *"Does intensive blood pressure lowering reduce cardiovascular events in patients with hypertension?"*)
- Four abstracts retrieved from PubMed, each pre-labeled as SUPPORTING, CONTRADICTING, or IRRELEVANT to the question

The model must respond with three things:

1. **Confidence Level** — one of five tiers: `SUPPORTED`, `MIXED`, `WEAK`, `CONTRADICTED`, or `INSUFFICIENT`
2. **Irrelevant Abstracts** — a list identifying which abstract(s) should be excluded from the synthesis
3. **Synthesis** — a narrative summary of the evidence and key caveats

The reference answer for each item (the correct confidence tier, which abstracts are irrelevant, and required caveats) is generated by a language model and then deterministically validated against the known abstract composition. A human reviewer should treat these as silver-standard labels rather than gold-standard human annotations.

### Confidence Tiers

Each item's ground-truth confidence tier is determined by the composition of its four abstracts:

| Tier | Abstract Composition |
|---|---|
| `SUPPORTED` | 3 supporting + 1 irrelevant, or 2 supporting + 2 irrelevant |
| `MIXED` | 2 supporting + 1 contradicting + 1 irrelevant |
| `WEAK` | 1 supporting + 2 contradicting + 1 irrelevant |
| `CONTRADICTED` | 3 contradicting + 1 irrelevant, or 2 contradicting + 2 irrelevant |
| `INSUFFICIENT` | 4 irrelevant |

In the v1 dataset, every item contains exactly four abstracts: the final abstract (labeled A4) is always IRRELEVANT, functioning as a distractor that a well-calibrated model should recognize and exclude.

### Domains

Version 1.0 covers two clinical domains:

- **Cardiology** — 6 items (blood pressure management, antiplatelet therapy, statins, sacubitril-valsartan, omega-3 fatty acids)
- **Endocrinology** — 4 items (vitamin D, testosterone replacement therapy, canagliflozin, denosumab)

## Evaluation Protocol

### Prompt format

Each evaluated model receives a prompt containing:

- The clinical question
- The four abstract texts labeled A1–A4, presented without their ground-truth tags
- Instructions to respond in three sections: **Confidence Level**, **Irrelevant Abstracts**, and **Synthesis / Key Caveats**

The model is not told the confidence tier options in advance; it must infer the appropriate level from the evidence.

### Rubric

Each model response is scored by a separate evaluator LLM (acting as a judge) on three dimensions, each 0–2:

**Evidence Consistency (0–2)**
Measures whether the model's stated confidence tier matches the ground-truth tier.
- 2 = tier matches exactly, or a directionally correct tier with appropriate reasoning
- 1 = tier is directionally close but not fully accurate (e.g., SUPPORTED when MIXED)
- 0 = tier contradicts the ground truth (e.g., SUPPORTED when MIXED or CONTRADICTED)

**Evidence Relevance (0–2)**
Measures whether the model correctly identified and excluded irrelevant abstracts.
- 2 = all irrelevant abstracts correctly identified and excluded from the synthesis
- 1 = irrelevant abstracts identified but not fully excluded from the reasoning
- 0 = irrelevant abstracts incorporated into the synthesis as if they were relevant

**Linguistic Confidence (0–2)**
Measures whether the model's hedging language is calibrated to the evidence tier.
- 2 = language precisely matches the tier (e.g., strong affirmation for SUPPORTED; explicit uncertainty for MIXED)
- 1 = language is partially aligned but over- or under-hedged
- 0 = language contradicts the tier (e.g., confident assertions for a WEAK or MIXED question)

**Total score per item: 0–6.** The maximum total score for a model across all 10 items is 60.

### Evaluation merge policy

Evaluation results accumulate across runs. If the same model is re-evaluated on the same item, the latest result replaces the previous one. Results from different models on the same item are preserved side-by-side. This allows incremental addition of new models without re-running existing ones.

## Results

Results reported for ClinTrialQA v1.0, 10 items (6 Cardiology, 4 Endocrinology), evaluated via the Groq API.

| Model | Total Score | % | Avg Consistency | Avg Relevance | Avg Linguistic |
|---|---|---|---|---|---|
| llama-3.3-70b-versatile | 44 / 60 | 73.3% | 1.60 | 2.00 | 0.80 |
| meta-llama/llama-4-scout-17b-16e-instruct | 39 / 60 | 65.0% | 1.30 | 1.50 | 1.10 |

**Key observations:**

- Both models score perfectly or near-perfectly on Evidence Relevance (2.00 and 1.50), meaning they generally recognize and call out the planted irrelevant abstract (A4).
- Linguistic calibration is the weakest dimension for `llama-3.3-70b-versatile` (0.80), suggesting it tends to use language that does not accurately reflect the assigned confidence tier even when it correctly identifies the tier.
- `llama-4-scout` shows more balanced dimensional scores but a lower overall total, suggesting less reliable tier identification.
- The MIXED tier is the most challenging: both models struggle to avoid defaulting toward SUPPORTED or INSUFFICIENT when evidence is genuinely split.

## Reproducing the Benchmark

The pipeline runs end-to-end in Google Colab using the provided notebook (`ClinTrialQA_Pipeline.ipynb`).

### Prerequisites

- A [Groq API key](https://console.groq.com) (free, no credit card required)
- An NCBI Entrez email address (any valid email; required by PubMed's API)
- Optionally, an [NCBI API key](https://ncbi.nlm.nih.gov/account) for a 10× rate limit increase

### Setup

Add the following secrets via the Colab Secrets panel (the key icon in the left sidebar):

| Secret Name | Description |
|---|---|
| `GROQ_API_KEY` | Your Groq API key |
| `ENTREZ_EMAIL` | Your email for NCBI E-utilities |
| `NCBI_API_KEY` | *(Optional)* Your NCBI API key |

### Pipeline cells

| Cell | Step | Description |
|---|---|---|
| 1 | Install & imports | Installs `groq`, `biopython`, `requests`, `tqdm`; imports all dependencies |
| 2 | Credentials & Drive | Sets API keys, mounts Google Drive for persistent storage |
| 3 | Configuration | Sets domains, item counts, model choices, and output paths |
| 4 | Pipeline functions | Defines all helper functions (LLM calls, PubMed search, throttling) |
| 5 | Dataset generation | Generates questions, retrieves and classifies PubMed abstracts, builds reference answers |
| 6 | Save dataset | Validates items and writes `clintrialqa_v1.json` |
| 7 | Evaluate models | Runs each model on all items; scores responses with the evaluator model |
| 8 | Save results | Merges new results with any prior runs; writes all four output files |
| 9 | Download outputs | Packages and downloads `dataset/` and `evaluation/` as zip archives |

### Adding a new model

To evaluate an additional model, edit the `MODELS` list in Cell 3:

```python
MODELS = ['llama-3.3-70b-versatile', 'your-new-model-id']
```

Then re-run Cells 7 and 8. Existing model results are preserved; only the new model's results are added.

### Rate limits

The pipeline implements adaptive throttling based on each model's RPM and TPM limits. Default configuration targets the free-tier Groq limits. Adjust `GROQ_MODEL_LIMITS` in Cell 4 if your account has higher limits.

## Limitations

**Small dataset size.** Version 1.0 contains 10 items across two domains. This is sufficient for a pilot evaluation but insufficient for reliable statistical ranking between models — score differences of a few points should not be over-interpreted.

**Silver-standard labels.** Reference answers and abstract classifications are generated by language models, not reviewed by clinical domain experts. The `annotation_rationale` and `required_caveats` fields reflect the generator model's judgment and may contain errors, particularly for nuanced clinical questions where domain expertise is required.

**Single-model evaluator.** The rubric scores are assigned by a language model judge rather than human raters. LLM judges are known to exhibit biases including length preference, self-similarity bias (favoring outputs that resemble their own style), and inconsistency across runs. Inter-rater reliability has not been measured.

**Retrieval-dependent construction.** Abstract composition (and therefore the assigned confidence tier) depends on what PubMed returns for the search queries generated by the pipeline. If queries are too broad or too narrow, the resulting abstract set may not faithfully represent the true evidence base for a question.

**No multi-turn or reasoning evaluation.** The benchmark evaluates a single-turn response. It does not assess chain-of-thought reasoning quality, the ability to ask clarifying questions, or behavior over extended clinical conversations.

**Domain coverage.** Only Cardiology and Endocrinology are covered in v1.0. The difficulty and behavior of models may differ substantially in other clinical specialties, particularly those with less RCT-heavy literature (e.g., rare diseases, psychiatry, surgery).

**Tier imbalance.** The v1.0 dataset has no CONTRADICTED or INSUFFICIENT items, and only one WEAK item. Models are not tested on the full range of confidence tiers. Coverage of all five tiers is intended in future versions.

**No adversarial cases.** All items follow a fixed four-abstract structure with exactly one irrelevant abstract. The benchmark does not test behavior when multiple abstracts are irrelevant, when all abstracts are relevant, or when the irrelevant abstract is superficially similar to the question (a harder distractor).

**API and model version drift.** Groq model availability and names may change. The pipeline is pinned to specific model identifiers; re-running with updated model strings may produce different results.
